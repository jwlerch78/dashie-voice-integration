# Dashie Voice Cross-Boundary Contracts

Registry of every contract shared between the integration (this repo), the Dashie for Home Assistant
add-on (dashie-ha-console repo), and satellites. Rule inherited from the Dashie postmortems:
before hand-mirroring anything across a boundary, add a row here — and prefer sharing
one copy over mirroring at all.

| Contract | This side | Other side | Notes |
|---|---|---|---|

The SAME `'gemini'` is the household `voice.sttProvider` value written by the console row `voice-ai-options.js` STT `id:'gemini'` | **Why the engine rides in the request:** HA's `/api/stt` carries no caller identity, and a tablet's STT pick is a PER-DEVICE override (Dashie contract row 78), so the entity is the only carrier of a per-device choice. **Kotlin side (revised 2026-10-08, John: Gemini replaces Deepgram in the console AND APK release):** the Android app gets an STT option `gemini` (VoiceAiOptions naming source; `VoicePreferences.STT_GEMINI`) whose provider posts PCM to HA `/api/stt/<this entity>` with the device's HA token, the same request `HaSttEngineDirectProvider` sends. So `'gemini'` is a JS↔Kotlin wire value too (Dashie JS_KOTLIN_CONTRACTS row, `lint:voice-options`), and the unique_id above is how the app finds the entity. Gate: dashie-ha-console `scripts/check-gemini-stt.mjs` (legs 5a–5d: query routing; leg 6: console id == `STT_GEMINI`) + this repo's `tests/test_stt_gemini.py`. | Tablet Gemini TTS stream (path K, 2026-10-12) | `tts_stream_view.py` `POST /api/dashie_voice/voice/tts-stream` (HA-token authed) `{text, voice?}` → `addon_bridge.stream_addon` POSTs the add-on's `/api/voice/tts` with `{text, voice, stream:true}` and pipes the bytes as they arrive (no buffering; `tests/test_tts_stream_view.py` asserts first audio arrives before the add-on finishes, and a buffering mutant reds it) | add-on `gemini-tts-lane.js` `streamWithKey`: `200 audio/pcm` (`X-Audio-Format: pcm_24000`, `X-Tts-Payer: key`) on the household's Gemini key, or `409 {reason:'no_key'}` / `409 {reason:'key_failed', provider, status}`, passed through VERBATIM; add-on unreachable → `503 {reason:'addon_unavailable'}` | The tablet pays with credits ITSELF on any non-200 (edge `gemini-tts`); nothing here spends credits. `status` is the key-health vocabulary GENERATED from the Dashie edge's `_shared/key-health-vocab.ts` into the add-on (Dashie JS_KOTLIN_CONTRACTS row 205); on `key_failed` the add-on writes the account's key-health row BEFORE answering, because the tablet force-refreshes its balance read on the 409. Only the audio-describing headers cross. Add-on gate: dashie-ha-console `scripts/check-key-first-tts.mjs` (S legs) |
| Tablet Gemini STT relay (2026-10-12; HV, O approved the build) | `stt_relay_view.py` `POST /api/dashie_voice/voice/stt-relay` (HA-token authed), body = 16 kHz mono PCM16 WAV → `addon_bridge.call_addon_raw_phased` POSTs the add-on's `/api/voice/stt?engine=gemini` and returns its status + JSON body VERBATIM. EVERY response carries `X-Dashie-Stt-Relay: 1` (so a tablet tells this route's answer from HA's 404 for a missing route = an older integration) | add-on `engines.js` `geminiSttBranch` (key first, then credits via the edge `gemini-stt`): `200 {text}` · `402 {error:'insufficient_credits'}` · `503 {error:'gemini_stt_no_key'}` · `502 …`; the relay's OWN failures: `503 {reason:'addon_unavailable'}` = NEVER SENT (no add-on / connection refused / connect timeout) · `504 {reason:'addon_outcome_unknown'}` = sent, then the exchange failed (the add-on may have billed credits: the tablet must NOT retry the turn elsewhere) | The split is conservative: only a connection-establishment failure is "never sent". `call_addon_raw_phased` is used by this view ONLY; `call_addon_raw` and every other caller keep the single `AddonUnavailable` (O's condition 1). Why it exists: the STT entity (`stt.py`) can only return HA's bare `SpeechResult` ERROR, which hides whether anything happened (Dashie `HV-STT-GEMINI-ALIGNMENT-PLAN.md` §9-§10). Test: `tests/test_stt_relay_view.py` (fake add-on over real HTTP; both arms over real TCP; 5 mutants red) |
