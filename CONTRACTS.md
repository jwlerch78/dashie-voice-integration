# Chickadee Cross-Boundary Contracts

Registry of every contract shared between the integration (this repo), the Chickadee
add-on (chickadee (add-on repo)), and satellites. Rule inherited from the Dashie postmortems:
before hand-mirroring anything across a boundary, add a row here — and prefer sharing
one copy over mirroring at all.

| Contract | This side | Other side | Notes |
|---|---|---|---|
| Add-on bridge HTTP surface | `const.py` (`ADDON_CONVERSE_PATH=/api/voice/converse`, `ADDON_PING_PATH=/api/ping`, `ADDON_STT_PATH=/api/voice/stt`, `ADDON_TTS_PATH=/api/voice/tts`, port 8099) | add-on HTTP server routes | Change together, never singly |
| STT turn shape | `stt.py` (POST audio/wav body → `{text}`) | add-on `engines.js` handleStt | 16 kHz mono PCM16 WAV in; empty `text` = no speech |
| TTS turn shape | `tts.py` (POST `{text, voice?}` → `audio/wav` bytes) | add-on `engines.js` handleTts | `voice` empty = engine/default voice (add-on `tts_voice` option) |
| TTS voice catalog | `tts.py` async_added_to_hass → POST `/api/voice/voices` → `{voices:[{voice_id,name}]}` → HA voice picker | add-on `engines.js` handleVoices (normalizes Kokoro `{id}` / Piper-shim `{voice_id}`) | Best-effort: empty catalog → free-text picker, synthesis unaffected |
| Bridge auth | `addon_bridge.py` (`X-Chickadee-Bridge-Secret` header). Secret priority: (1) Supervisor discovery via `config_flow.async_step_hassio` → entry data → `set_bridge_config`; (2) legacy file read `<ha-config>/.chickadee/bridge_secret`, glob `addon_configs/*chickadee/bridge_secret` | add-on publishes `{service:"chickadee", config:{host,port,secret}}` to Supervisor `/discovery` on every start (`discovery.js`; config.yaml `hassio_api`+`discovery`) AND still writes the file copies for pre-discovery integrations; auth ENFORCED from birth | Discovery = the MQTT-broker credential pattern. ⚠️ HA Core canNOT read /addon_configs on HAOS (2026-07-25); file-in-ha-config stays as legacy fallback only. Pattern to back-port to Dashie's bridge auth |
| VoiceRequest / turn shape | `conversation.py` payload build + turn handling (`voice`/`text`/`action`/`steps`/`client_tool`/`unsupported_tool`) | add-on brain runtime | Pass-through philosophy: unknown fields must survive; add-on owns overrides (`retain_mode`, route). `assistant_name` (optional) → brain `{{ASSISTANT_NAME}}` persona; absent = brain default |
| Brain entity shape | `entity_context.py` (`{entity_id, domain, friendly_name, state, area?, aliases?}`) | brain prompt builder | Source contract: Dashie 20260717_HA_ENTITY_EXPOSURE_CONTRACT |
| Add-on slug | `const.py` candidates (`local-chickadee`, `addon_local_chickadee`) | chickadee (add-on repo) `config.yaml` `slug: chickadee` | Slugs are immutable once shipped |
| Console core ↔ Dashie delta (repo inversion, 2026-07-27) | — | chickadee (add-on repo) `chickadee/frontend/console/` is **CANONICAL SOURCE** — the console is developed there. The private dashie-console repo carries only the Dashie delta (its `delta-manifest.txt`: subscription/paywall modules + family-product pages + its own `js/lib/brand.js`) and vendors the core FROM chickadee via `scripts/vendor-core.sh` (git-archive + re-brand statics + inject delta `<script>` block) | Seam rules: core reaches delta modules ONLY via guarded window access (`window.SubscribeGate?.`, typeof-guarded page registry — a missing module must no-op); a path is core-owned OR delta-owned, never both (vendor script errors); `index.html`'s `DELTA-SCRIPTS` block ships EMPTY in the public tree and is generated on the Dashie side. Gates: chickadee `scripts/check-console-tree.sh` (no delta files/paywall strings/unguarded delta globals; wired into release.sh) + vendor-core.sh's own sanity gate. ⚠️ Do NOT edit vendored core files in dashie-console — edit in the public repo, then re-vendor |
| Disclosure docs (`PRIVACY.md`, `PROVENANCE.md`) | Mirrored copies in this repo root, each carrying a `MIRRORED FILE` header naming the canonical URL | chickadee (add-on repo) root — **canonical** | HACS installs THIS repo, so the disclosure has to live here too; a link-out leaves the HACS front door with no disclosure surface of its own (R3 audit T2-D). Hand-mirror, deliberately: edit canonical → copy here in the same change. Drift is the exact failure that produced R3's Tier-1 findings (docs frozen 07-27, code moved 07-28), so treat a stale mirror as a bug. ⚠️ NOT yet gated — the audit's recommended `lint:disclosure` (assert mirrors are byte-identical below the header) belongs in the add-on's `release.sh` beside `check-console-tree.sh` |
| Console ↔ add-on API | — | add-on serves the SPA at Ingress root; SPA (console-auth.js, vendored) probes `GET /api/runtime` (`addon:true`, `email_auth:true`) and drives `/api/auth/*` (device flow + `email-signin`/`email-signup`), `/api/voice/engines|probe|preview|discover|converse-local`, `/api/keys/*`, `/api/settings/*` | Contract owner is the dashie-console SPA (shared with the Dashie add-on's server); `email_auth` is the capability flag that lights the email login button |
| Kiosk LAN-sharing lane | `voice_view.py` serves canonical `/api/chickadee/voice/status|converse|session|live-token` + `/api/chickadee/account/authorize` WITH `/api/dashie/...` legacy aliases (HA-token authed; **the `dashie` aliases are a wire contract with shipped Dashie APKs — never remove while those apps are fielded**; both `X-Chickadee-Brain-Route` and `X-Dashie-Brain-Route` response headers carry the route) → `account_bridge.py` → add-on `/api/internal/sharing-status|account-credential|voice-config|authorize-device` (bridge-secret gated) | chickadee (add-on repo) `server/api/internal.js` (0.6.0) | Ownership guard: when the Dashie integration is ALSO installed, chickadee registers only if dashie has ceded (`hass.data['dashie']['voice_views_ceded']`, set by dashie-ha-integration ≥93ad4a8); decided at HA start. Sharing gate = account `voice.householdSharing`, fails closed |
